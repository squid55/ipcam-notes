# Video Analytics (영상 분석)

> 영상에서 「무엇이 어디에 있고 어떻게 움직였는가」를 뽑아내는 일.
> 감시 제품에서는 대개 **사람·차량 검출 + 추적 + 규칙 판정**의 조합이다.

## 왜 필요한가

24시간 녹화를 사람이 다 볼 수 없다. 「이 구역에 사람이 들어왔을 때만 알려 달라」가
실제 요구이고, 그것을 만드는 것이 영상 분석이다.

그리고 이것이 제품을 가르는 지점이 됐다. 해상도와 코덱은 평준화됐고,
**오검출을 얼마나 줄였는지**가 경쟁 요소다.

## 최소 이해 수준

- **단계가 나뉘어 있다.**
  ```
  검출(detection)    프레임에서 객체 위치와 종류를 찾는다
  추적(tracking)     프레임 사이에서 같은 객체를 이어 붙여 ID 를 준다
  규칙 판정(rule)    선 통과 · 영역 침입 · 배회 · 방향 위반 등
  이벤트 발생        알림 · 녹화 표시 · 메타데이터 전송
  ```
  **추적이 없으면 규칙을 만들 수 없다.** 「들어왔다」는 판정 자체가
  같은 객체를 프레임 간에 연결해야 성립한다.
- **고전 기법과 학습 기반.**

  | | 고전 (배경 차분 등) | 학습 기반 (CNN 검출) |
  |---|---|---|
  | 비용 | 매우 낮다 | 가속기 필요 |
  | 종류 구분 | 못 한다 (움직이는 덩어리) | 사람·차량·동물 구분 |
  | 오검출 | 나뭇잎·비·그림자에 반응 | 훨씬 적다 |
  | 정지 객체 | 못 찾는다 | 찾는다 |

  **「움직임 감지」와 「사람 검출」은 다른 기능**이고,
  제품 설명에서 흔히 뒤섞인다.
- **모델은 대개 단일 단계(one-stage) 검출기다.** YOLO 계열 · SSD · CenterNet.
  입력은 정해진 크기(예: 640×640)로 리사이즈된 RGB, 출력은
  경계 박스 + 클래스 + 신뢰도의 목록이다.
- **후처리 두 가지를 알아야 한다.**
  - **신뢰도 임계값** — 낮추면 놓침이 줄고 오검출이 는다
  - **NMS(비최대 억제)** — 겹친 박스를 하나로 합친다. IoU 임계값으로 조절
- **추적의 기본형.** 이전 프레임 박스와 현재 박스를 IoU 로 짝지어
  같은 ID 를 유지한다. 여기에 칼만 필터로 예측을 더한 것이 `SORT`,
  외형 특징까지 쓰는 것이 `DeepSORT` 계열이다.
- **가장자리(edge)에서 할지 서버에서 할지.**

  | | 카메라에서 | 서버에서 |
  |---|---|---|
  | 대역폭 | 이벤트만 보내므로 적다 | 전 영상을 보내야 한다 |
  | 연산 | 카메라에 가속기 필요 | GPU 서버 한 대로 여러 채널 |
  | 모델 교체 | 펌웨어 업데이트 | 서버만 바꾸면 된다 |
  | 사생활 | 영상이 밖으로 안 나갈 수 있다 | 영상이 서버로 간다 |

- **가속기 종류.** NPU(SoC 내장) · 별도 추론 가속기 · GPU.
  프레임워크가 다르다 — TFLite · ONNX Runtime · TensorRT · 벤더 SDK.
  **모델을 그 장치용 형식으로 변환**해야 돌아간다.
- **평가 지표.** 정밀도(precision) · 재현율(recall) · mAP.
  감시 제품에서 실질적으로 중요한 것은 **시간당 오알림 건수**다.
  mAP 가 좋아도 하루에 200번 울리면 사용자는 기능을 끈다.

## 직접 해보기

### 1. 가장 가벼운 것부터: 움직임만

```python
import cv2
cap = cv2.VideoCapture("rtsp://<주소>/stream")
bg = cv2.createBackgroundSubtractorMOG2(500, 30, detectShadows=False)
while True:
    ok, f = cap.read()
    if not ok: break
    small = cv2.resize(f, (480, 270))          # 축소해서 처리
    m = bg.apply(small)
    moved = cv2.countNonZero(m) / m.size
    if moved > 0.02:
        print(f"움직임 {moved*100:.1f}%")
```

**축소 처리 + 비율 임계값**이 실용적인 1차 필터다.
여기서 걸러진 프레임만 무거운 검출로 넘기면 비용이 크게 줄어든다.

### 2. ONNX 검출 모델 돌려 보기

```python
import cv2, numpy as np
net = cv2.dnn.readNetFromONNX("yolo.onnx")
img = cv2.imread("t.jpg")
blob = cv2.dnn.blobFromImage(img, 1/255.0, (640,640), swapRB=True, crop=False)
net.setInput(blob); out = net.forward()
print("출력 형태:", out.shape)
```

⚠ **전처리가 모델마다 다르다.** 스케일 · 평균 차감 · 채널 순서 ·
레터박스 방식이 학습 때와 같아야 한다. 다르면 오류 없이 **정확도만 떨어진다.**

### 3. 추론 시간 재서 채널 수 계산

```python
import time
t = time.perf_counter()
for _ in range(20): net.setInput(blob); net.forward()
ms = (time.perf_counter()-t)/20*1000
print(f"{ms:.1f} ms/프레임 → {1000/ms:.1f} fps")
```

```
채널 수 = 추론 가능 fps ÷ 채널당 필요 fps
```
초당 30회 추론이 가능하고 채널당 5fps 로 분석하면 **6채널**이다.
**매 프레임 추론하지 않는 것**이 채널 수를 늘리는 가장 큰 수단이다.

### 4. 추적을 붙여 보기

```python
tracks = {}          # id -> (cx, cy)
next_id = 0

def match(boxes):
    global next_id
    out = []
    used = set()
    for b in boxes:
        cx, cy = b[0]+b[2]/2, b[1]+b[3]/2
        best, bd = None, 1e9
        for tid, (px, py) in tracks.items():
            if tid in used: continue
            d = (cx-px)**2 + (cy-py)**2
            if d < bd: best, bd = tid, d
        if best is not None and bd < 80**2:
            tracks[best] = (cx, cy); used.add(best); out.append((best, b))
        else:
            tracks[next_id] = (cx, cy); out.append((next_id, b)); next_id += 1
    return out
```

거리 기반 최근접 짝짓기만으로도 동작을 볼 수 있다.
**사람이 교차하면 ID 가 바뀌는 것**을 직접 확인하게 된다 —
그 문제가 DeepSORT 같은 방법이 존재하는 이유다.

### 5. 규칙 판정: 선 통과

```python
def crossed(prev, cur, line):
    (x1,y1),(x2,y2) = line
    def side(p):
        return (x2-x1)*(p[1]-y1) - (y2-y1)*(p[0]-x1)
    return side(prev) * side(cur) < 0      # 부호가 바뀌면 통과
```

**방향까지 필요하면** 부호의 전환 방향을 본다.
「들어옴」과 「나감」을 구분하는 것이 실제 요구다.

### 6. 오검출률을 실제로 재기

가장 중요한 시험이고 가장 자주 생략된다.

```
① 실제 설치 장소에서 24시간 이벤트를 기록한다
② 각 이벤트의 스냅샷을 사람이 확인해 참·거짓을 표시한다
③ 시간당 오알림 건수를 센다
④ 임계값을 바꿔 ①~③ 을 반복한다
```

⚠ 공개 데이터셋 성능은 참고값이다. **비 오는 밤 · 역광 출입구 ·
흔들리는 나무 · 벌레가 렌즈에 붙은 상황**이 실제 오검출의 대부분이고,
데이터셋에는 거의 없다.

### 7. 메타데이터를 표준 경로로 내보내기

ONVIF Profile M 이 분석 결과를 RTP 메타데이터 트랙으로 보내는 규격이다.
VMS 와 연동하려면 자체 형식보다 이쪽이 낫다. → [ONVIF](../네트워크/ONVIF.md)

## 더 들어가면

- **모델 양자화.** float32 → int8 로 바꾸면 크기와 연산이 크게 줄고
  많은 NPU 는 int8 만 지원한다. 정확도가 조금 떨어지므로
  **양자화 후 정확도를 다시 재야 한다.**
- **ROI 와 마스크.** 하늘 · 도로 밖 · 이웃 창문을 분석 대상에서 제외한다.
  오검출을 줄이는 가장 값싼 방법이고, **사생활 요구에도 맞는다.**
- **시간대별 파라미터.** 낮과 밤의 영상 특성이 다르다.
  IR 조명이 켜지면 흑백이 되고 노이즈가 늘어 임계값이 달라져야 한다.
  → [이미지 센서](../영상/이미지센서.md)
- **압축 화질의 영향.** 비트레이트를 낮추면 블록 노이즈가 생겨 검출률이 떨어진다.
  **분석용 스트림과 녹화용 스트림을 분리**하고, 분석용은 해상도를 낮추되
  비트레이트를 과하게 줄이지 않는 구성이 흔하다. → [H.264](../압축/H264.md)
- **재식별(Re-ID).** 카메라를 넘나드는 같은 사람을 잇는 문제.
  훨씬 어렵고, 사생활 쟁점이 크다.
- **사생활과 법적 제약.** 얼굴 인식과 개인 식별은 나라·용도별로 규제가 다르다.
  공공 조달에서는 **어떤 정보를 저장하고 얼마나 보관하는지**가 요구사항으로 들어온다.
  분석 결과도 개인정보가 될 수 있으므로 접근 통제와 기록이 필요하다.
  → [감사기록](../보안/감사기록.md)

## 흔한 오해

### 「모델을 좋은 것으로 바꾸면 오알림이 줄어든다」

검출 정확도와 알림 품질은 다르다. 사람을 정확히 찾아도
「지나가는 행인」을 침입으로 판정하면 오알림이다.
**규칙 설계와 영역 설정이 모델 교체보다 효과가 큰 경우가 많다.**

### 「매 프레임 추론해야 정확하다」

사람의 이동 속도를 생각하면 5fps 로도 충분하다.
남는 시간에 추적으로 메우면 정확도는 비슷하고 **비용은 1/6** 이 된다.

### 「가속기가 있으면 채널 수는 문제없다」

디코딩도 비용이다. 16채널을 분석하려면 16채널을 먼저 디코딩해야 하고,
그쪽이 먼저 한계에 닿는 경우가 흔하다. → [하드웨어 인코더](../압축/하드웨어인코더.md)

### 「데이터셋 mAP 가 높으면 제품 성능도 좋다」

설치 각도 · 조명 · 렌즈 왜곡이 학습 데이터와 다르다.
천장에 달린 카메라의 위에서 본 사람은 정면 데이터로 학습한 모델이 잘 못 찾는다.
**현장 영상으로 재보는 것 외에 방법이 없다.**

### 「학습 기반이면 고전 기법은 필요 없다」

두 단계로 쓰는 것이 실전 구성이다. 배경 차분으로 후보 구간만 골라
그때만 추론하면 **전력과 비용이 크게 준다.** 배터리·저전력 제품에서는 필수적이다.

### 「분석은 카메라에서 하는 게 항상 낫다」

모델 교체가 펌웨어 업데이트가 된다는 뜻이다. 모델이 자주 바뀌는 초기 제품에서는
서버 쪽이 운영하기 쉽다. **사생활과 대역폭이 중요하면 카메라 쪽**이고,
운영 유연성이 중요하면 서버 쪽이다.
