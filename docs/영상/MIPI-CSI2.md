# MIPI CSI-2

> 이미지 센서와 SoC 를 잇는 고속 직렬 인터페이스.
> 카메라 데이터가 실제로 흘러 들어오는 물리 경로다.

## 왜 필요한가

「최대 해상도 × 프레임레이트」의 상한이 여기서 정해진다.
센서가 4K60 을 낼 수 있어도 CSI-2 레인이 부족하면 그 조합을 쓸 수 없다.

그리고 카메라가 안 잡히는 문제의 상당수가 이 계층이다.
레인 수 · 극성 · 클럭 모드 설정이 틀리면 **드라이버는 정상인데 유효 프레임이 없다.**
증상이 인코더 고장처럼 보이기 때문에 엉뚱한 곳을 파게 된다.

## 최소 이해 수준

![CSI-2 링크 구성. 클럭 한 쌍과 데이터 레인 여러 쌍의 차동 신호. `link-frequencies` 는 클럭이고 DDR 이므로 비트레이트는 두 배다.](../fig/csi2-lanes.svg)

- **차동 신호 쌍(레인)을 여러 개 묶는다.** 클럭 레인 1개 + 데이터 레인 1·2·4개가 흔하다.
  각 레인은 D-PHY 차동 쌍이라 선이 2개다. 4레인이면 데이터 8선 + 클럭 2선.
- **대역폭 계산.**
  ```
  필요 대역폭 = 가로 × 세로 × 비트깊이 × fps × (1 + 블랭킹 여유)
  가용 대역폭 = 레인 수 × 레인당 속도
  ```
  1920×1080 × 10bit × 30fps ≈ 622 Mbps. 블랭킹까지 보면 800 Mbps 쯤 필요하다.
  레인당 1 Gbps 라면 1레인으로도 되지만, 4K30 (≈2.5 Gbps)은 **2레인 이상**이 필요하다.
- **가상 채널(VC)과 데이터 타입(DT).** 한 링크에 여러 스트림을 실을 수 있다.
  VC 로 스트림을 구분하고, DT 로 형식을 구분한다.
  `0x2B` = RAW10, `0x2C` = RAW12, `0x1E` = YUV422 8bit 등.
- **패킷 구조.** 짧은 패킷(프레임 시작·끝)과 긴 패킷(한 줄의 픽셀 데이터)이 있다.
  줄마다 긴 패킷 하나가 오고, **프레임 경계는 짧은 패킷으로 표시**된다.
- **클럭 모드 두 가지.**
  - **연속(continuous)** — 클럭 레인이 항상 돈다
  - **비연속(non-continuous)** — 데이터가 없을 때 클럭이 저전력 상태로 내려간다

  **수신기와 센서 설정이 일치해야 한다.** 틀리면 첫 프레임부터 깨진다.
- **레인 수는 설정 항목이다.** 센서와 수신기 양쪽에 적어야 한다.
  디바이스트리에 `data-lanes = <1 2>;` 처럼 쓴다. → [디바이스 트리](../BSP/디바이스트리.md)
- **포트가 여러 개일 수 있다.** SoC 에 CSI 수신기가 2개 있어도
  **ISP·펌웨어가 한쪽만 읽도록 설정된 경우가 있다.**
- **C-PHY 라는 변종이 있다.** D-PHY 가 차동 쌍이고, C-PHY 는 3선 1조로
  같은 선 수에서 더 높은 처리량을 낸다. 감시 카메라에서는 D-PHY 가 일반적이다.

## 직접 해보기

### 1. 디바이스트리의 CSI 설정 확인

```bash
dtc -I fs -O dts /proc/device-tree -o /tmp/cur.dts 2>/dev/null
grep -n -B3 -A12 'data-lanes' /tmp/cur.dts
```

센서 쪽과 수신기 쪽의 `data-lanes` 개수가 **같아야** 한다.
`remote-endpoint` 로 서로를 가리키는지도 확인한다.

```dts
sensor_out: endpoint {
    remote-endpoint = <&csi_in>;
    data-lanes = <1 2>;
    clock-lanes = <0>;
    link-frequencies = /bits/ 64 <456000000>;
};
```

⚠ `link-frequencies` 는 **레인당 클럭 주파수**이고, DDR 이므로
실제 비트레이트는 그 두 배다. 456 MHz → 912 Mbps.

### 2. 미디어 그래프에서 링크 확인

```bash
media-ctl -p
```

`sensor → csi → isp → video node` 링크가 보이고 `ENABLED` 인지 확인한다.

```bash
# 링크가 꺼져 있으면 켠다
media-ctl -l '"sensor 1-001a":0 -> "csi":0 [1]'
media-ctl -V '"sensor 1-001a":0 [fmt:SRGGB10/1920x1080]'
```

**포맷을 링크마다 맞춰 줘야** 스트리밍이 시작된다.
한 단계라도 어긋나면 `VIDIOC_STREAMON` 이 실패한다.

### 3. 수신기 오류 카운터 보기

CSI 수신기 드라이버가 오류를 세는 경우가 많다.

```bash
dmesg -w &
# 스트리밍 시작
v4l2-ctl -d /dev/video0 --stream-mmap --stream-count=30
```

`dmesg` 에 나오는 것으로 원인이 갈린다.

| 메시지 | 뜻 |
|---|---|
| `ECC error` · `CRC error` | 배선·신호 품질 문제. 노이즈나 배선 길이 |
| `SoT sync error` | 클럭 모드나 레인 속도 불일치 |
| `lane mismatch` · `unexpected data type` | 설정값이 센서와 다르다 |
| 아무 것도 없음 | **데이터가 아예 오지 않는다** — 센서 초기화나 전원 |

### 4. 프레임이 오는지만 먼저 확인

```bash
v4l2-ctl -d /dev/video0 --stream-mmap --stream-count=10 --verbose
```

`VIDIOC_DQBUF` 가 타임아웃으로 실패하면 유효 프레임이 오지 않는 것이다.
**이 시점에서 인코더·네트워크·응용을 볼 이유가 없다.**

### 5. 센서 쪽 통신이 되는지 먼저 가르기

```bash
i2cdetect -y -r 1
```

I2C 는 CSI-2 와 **별개의 선**이다. I2C 는 되는데 프레임이 안 오면
「설정은 보냈지만 데이터 경로가 안 열린 것」이고, 문제 범위가 CSI-2 로 좁혀진다.
→ [UART · I2C · SPI · GPIO](../BSP/버스.md)

### 6. 레인 수를 줄여서 시험

4레인에서 안 되면 1레인 + 낮은 해상도로 내려 본다.
동작하면 **신호 품질이나 고속 설정 문제**이고, 그래도 안 되면 설정 자체가 틀린 것이다.
문제를 반으로 자르는 가장 빠른 방법이다.

## 더 들어가면

- **블랭킹.** 줄 사이(HBLANK)와 프레임 사이(VBLANK)의 여유 구간.
  센서 레지스터로 조절하며, **프레임레이트를 미세 조정하는 실제 수단**이다.
  대역폭 계산에서 이 여유를 빼면 실제보다 낙관적인 값이 나온다.
- **라인 버퍼와 백프레셔.** 수신기 뒤(ISP·메모리)가 못 받아 주면
  라인 버퍼가 넘치고 프레임이 깨진다. 메모리 대역폭 문제가
  **CSI 오류처럼 보이는 경우**가 있다.
- **DPHY 타이밍 파라미터.** `hs-settle` 등의 값을 드라이버나 디바이스트리에서
  맞춰야 하는 플랫폼이 있다. 틀리면 첫 몇 바이트가 깨진다.
- **CSI-2 over D-PHY vs CSI-3.** CSI-3 은 UniPro 기반으로 거의 쓰이지 않는다.
  실무에서 만나는 것은 CSI-2 다.
- **직렬화기·역직렬화기(SerDes).** 차량·산업용에서는 CSI-2 를 GMSL·FPD-Link 로
  변환해 수 미터 이상 보낸다. 양쪽에 변환 칩이 들어간다.
- **가상 채널 활용.** HDR 에서 노출이 다른 두 프레임을 서로 다른 VC 로 동시에 보낸다.
  수신기가 VC 를 분리해 두 스트림으로 넘긴다.

## 흔한 오해

### 「영상이 안 나오면 인코더 문제다」

가장 값비싼 오해다. 유효 프레임이 없으면 **모든 스트림이 동시에 고장난다** —
H.264 는 이상한 색 노이즈로, MJPEG 은 프레임 0 타임아웃으로 나타난다.
증상이 코덱마다 달라 보여서 인코더를 의심하게 되지만 원인은 하나다.

실측: 센서를 다른 MIPI 포트로 옮겼더니 그대로 이 상태가 됐다.
ISP 쪽이 **원래 한쪽 포트만 읽도록 설정**돼 있었고, 네트워크·웹·인코더·전송은
모두 정상이었다. 해결은 센서를 원래 포트로 되돌리고 콜드 부팅한 것이었다.

⇒ 영상이 안 나오면 **인코더를 파기 전에 센서 입력 경로부터 확인한다.**
`--stream-count=1` 로 프레임 하나가 오는지 보는 것이 첫 시험이다.

### 「`dmesg` 에 센서 초기화 로그가 있어야 한다」

센서를 커널 드라이버가 아니라 **별도 펌웨어(비디오 코어 등)가 관리**하는 플랫폼에서는
`dmesg` 에 아무 것도 안 찍힌다. 로그가 없다고 해서 센서가 없는 것이 아니다.
그 플랫폼의 로그 창구를 따로 찾아야 한다.

### 「레인이 많으면 무조건 낫다」

핀을 더 쓰고 기판 배선이 까다로워진다. 필요한 대역폭을 계산해서
**한 단계 여유만 두는 것**이 실무적이다.

### 「CSI-2 설정은 센서 쪽만 맞추면 된다」

센서와 수신기 양쪽이다. 그리고 디바이스트리의 endpoint 는 **서로를 가리켜야** 한다.
한쪽만 고치면 링크가 만들어지지 않고, 그때 `media-ctl -p` 에 링크가 안 보인다.

### 「해상도를 낮추면 대역폭 문제가 없다」

비트 깊이와 프레임레이트도 곱해진다. 720p 라도 12bit 120fps 는
1080p 10bit 30fps 보다 대역폭이 크다. **세 값을 함께** 계산한다.
