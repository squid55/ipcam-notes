# ISP 파이프라인

> 센서의 원시 데이터를 사람이 보는 영상으로 바꾸는 처리 사슬.
> 대부분 SoC 안의 전용 하드웨어 블록으로 들어 있다.

## 왜 필요한가

센서 출력은 그대로는 볼 수 없다. 색이 없고, 밝기가 치우쳐 있고, 노이즈가 있고,
렌즈 때문에 가장자리가 어둡고 휘어 있다. ISP 가 이 전부를 순서대로 고친다.

같은 센서를 쓴 두 카메라의 화질이 크게 다른 이유가 여기 있다.
**부품이 아니라 튜닝이 화질을 가른다.**

## 최소 이해 수준

- **순서가 정해져 있다.** 각 단계가 앞 단계의 출력을 전제한다.
  대략 이런 흐름이다.

  ```
  센서 RAW (베이어, 10~14bit)
    ↓  결함 화소 보정 (DPC)
    ↓  블랙 레벨 보정 (BLC)      — 빛이 0일 때의 기준값을 뺀다
    ↓  렌즈 셰이딩 보정 (LSC)    — 가장자리 어두움을 보정
    ↓  노이즈 제거 (RAW 단)
    ↓  화이트 밸런스 (AWB 게인)  — R·B 게인으로 색 온도 보정
    ↓  디모자이킹                — 여기서 처음 RGB 가 된다
    ↓  색 보정 행렬 (CCM)        — 센서 색을 표준 색으로
    ↓  감마 · 톤 매핑
    ↓  RGB → YUV 변환
    ↓  선명도 (sharpen) · 색 노이즈 제거
    ↓  스케일 · 크롭
  출력 (NV12 등)
  ```

- **화이트 밸런스는 디모자이킹 전에 한다.** 베이어 상태에서 R·B 채널에 게인을 곱하는 편이
  싸고 정확하다. 순서를 바꾸면 색이 어긋난다.
- **노이즈 제거와 선명화는 서로 싸운다.** 노이즈를 지우면 디테일도 지워지고,
  선명하게 하면 노이즈도 같이 도드라진다. 튜닝의 핵심 맞바꿈이다.
- **3A 가 ISP 를 조종한다.** 자동 노출(AE) · 자동 화이트밸런스(AWB) · 자동 초점(AF).
  ISP 가 통계값을 내고, 3A 알고리즘이 그것을 보고 센서와 ISP 파라미터를 다음 프레임에 반영한다.
  → 되먹임 고리이므로 **한 프레임씩 늦다.**
- **하드웨어 ISP 는 대개 문서가 닫혀 있다.** SoC 벤더가 튜닝 도구와 파라미터 파일을
  같이 준다. 소스가 아니라 **바이너리 + 설정 파일**로 오는 경우가 많다.
- **소프트웨어 ISP 도 있다.** `libcamera` 의 `softISP`, 라즈베리파이의 처리 경로 등.
  CPU 를 먹지만 들여다볼 수 있어 학습에 좋다.

## 직접 해보기

### 1. ISP 를 거친 출력과 안 거친 출력 비교

```bash
# RAW (ISP 우회)
v4l2-ctl -d /dev/video0 --set-fmt-video=pixelformat=RG10 \
  --stream-mmap --stream-count=1 --stream-to=raw.bin

# ISP 통과 (YUV)
v4l2-ctl -d /dev/video0 --set-fmt-video=pixelformat=NV12 \
  --stream-mmap --stream-count=1 --stream-to=isp.nv12
```

두 파일을 각각 이미지로 바꿔 나란히 본다. 색 · 밝기 · 노이즈 차이가 ISP 가 한 일이다.

### 2. 화이트 밸런스를 손으로 틀어 보기

```bash
v4l2-ctl -d /dev/video0 --list-ctrls | grep -iE 'white|balance|temperature'
v4l2-ctl -d /dev/video0 --set-ctrl=white_balance_automatic=0
v4l2-ctl -d /dev/video0 --set-ctrl=white_balance_temperature=2800   # 백열등
v4l2-ctl -d /dev/video0 --set-ctrl=white_balance_temperature=6500   # 주광
```

흰 종이를 찍으면서 바꿔 본다. **자동을 끄지 않으면 설정이 곧바로 되돌아간다.**

### 3. 3A 가 수렴하는 데 걸리는 시간 재기

밝은 곳에서 어두운 곳으로 카메라를 돌리고 몇 프레임 만에 밝기가 안정되는지 센다.

```bash
ffmpeg -i /dev/video0 -vf "select=lt(n\,60)" -vsync 0 -f image2 f%03d.png

# 각 프레임 평균 밝기
for f in f*.png; do printf '%s ' "$f"; convert "$f" -colorspace gray -format '%[mean]' info:; echo; done
```

값이 평평해지는 지점이 수렴 시점이다. 이것이 길면 실사용에서 **장면 전환 때 눈에 띈다.**

### 4. libcamera 로 파이프라인 들여다보기

지원 보드라면 단계별 통계와 파라미터를 볼 수 있다.

```bash
cam --list
libcamera-hello --list-cameras
```

### 5. 미디어 그래프 확인

ISP 가 별도 서브디바이스로 노출되는 플랫폼이라면 연결 관계가 보인다.

```bash
media-ctl -p
```

`sensor → csi → isp → video node` 형태의 링크가 보인다.
어느 노드가 활성인지 여기서 판단한다.

## 더 들어가면

- **튜닝 워크플로.** 표준 차트(ColorChecker, 해상도 차트, 회색 계조)를 정해진 조명에서
  찍고 측정값을 맞춰 간다. 눈으로만 하면 재현되지 않는다.
- **CCM 계산.** 센서가 본 색과 목표 색 사이의 3×3 행렬을 최소자승으로 푼다.
  광원마다 다른 행렬이 필요하다.
- **로컬 톤 매핑.** 화면 전체가 아니라 영역별로 다른 곡선을 적용한다.
  역광에서 실내와 창밖을 동시에 살릴 수 있지만 후광(halo)이 생기기 쉽다.
- **시간축 노이즈 제거(TNR).** 이전 프레임과 섞어 노이즈를 줄인다.
  효과가 크지만 움직이는 물체에 잔상이 남는다. 감시 영상에서는 **번호판·얼굴이 뭉개진다.**
- **ISP 지연.** 파이프라인 단계마다 프레임 버퍼가 필요해 지연이 쌓인다.
  실시간 감시에서 전체 지연 예산의 상당 부분을 차지한다.

## 흔한 오해

### 「ISP 는 후보정이다」

후보정은 완성된 영상을 고치는 것이고, ISP 는 **영상을 만드는 과정**이다.
RAW 에서만 할 수 있는 보정(블랙 레벨, 렌즈 셰이딩, 디모자이킹)이 여기 있다.

### 「선명도를 올리면 화질이 좋아진다」

선명화는 경계에 대비를 더하는 것이라 없던 정보를 만들지 않는다.
과하면 윤곽에 흰 테두리가 생기고, 압축 단계에서 **비트레이트만 잡아먹는다.**
→ [H.264](../압축/H264.md)

### 「자동 모드가 항상 최선이다」

고정 설치 감시 카메라는 장면이 거의 변하지 않는다. 자동이 오히려
지나가는 헤드라이트에 반응해 화면 전체가 어두워지는 문제를 만든다.
**노출 측광 영역을 제한하거나 수동 고정**이 나은 경우가 많다.

### 「센서만 바꾸면 된다」

ISP 파라미터는 센서별로 다시 튜닝해야 한다. 같은 파라미터를 쓰면
색이 틀어지고 노이즈 제거 강도가 맞지 않는다.
