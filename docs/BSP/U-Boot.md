# U-Boot

> 임베디드 리눅스에서 가장 널리 쓰이는 부트로더. 전원이 들어온 뒤 커널을 메모리에 올려
> 넘겨주는 일을 하고, 그 전에 사람이 개입할 수 있는 명령 프롬프트를 제공한다.

## 왜 필요한가

**보드에 뭔가를 처음 올릴 때 유일한 통로**다. 리눅스가 뜨지 않는 상태에서도
플래시를 쓰고 네트워크로 이미지를 받을 수 있다. 개발 중에는 이것이 생명줄이다.

동시에 **보안 관점에서는 가장 약한 고리**다. 부트로더는 커널·인증·무결성 검증보다
먼저 실행되므로, 여기에 접근한 사람은 그 모든 보호를 우회할 수 있다.
개발 편의와 제품 보안이 정면으로 충돌하는 자리다.

## 최소 이해 수준

- **실행 순서.**
  `ROM 부트코드 → SPL(1차) → U-Boot(2차) → 커널 → init`
  SPL 은 DRAM 초기화만 하는 작은 조각이고, 그다음 본체가 올라온다.
- **자동부팅과 중단.**
  `bootdelay` 초 동안 기다리다 `bootcmd` 를 실행한다. 그 사이 키를 누르면 프롬프트로 빠진다.
- **환경변수.**
  `bootcmd`·`bootargs`·`ipaddr` 등이 플래시에 저장된다.
  `printenv` / `setenv` / `saveenv` 로 다룬다.
  **`saveenv` 를 하지 않으면 재부팅 시 사라진다** — 저장 영역이 깨져 있으면
  `bad CRC` 경고가 뜨고 매번 기본값으로 시작한다.
- **`bootargs` 가 커널에 전달된다.**
  루트 파일시스템 위치·콘솔 장치가 여기서 정해진다.
  부팅이 중간에 멈추면 이 값을 먼저 본다.
- **디바이스 트리를 함께 넘긴다.**
  커널 이미지와 DTB 를 각각 메모리에 올리고 주소를 알려준다.
  `bootm <커널주소> - <dtb주소>` 형태.
- **주요 명령.**
  `md`·`mw`(메모리 읽기·쓰기) · `sf`(SPI 플래시) · `nand` · `mtd` ·
  `tftp`·`dhcp`(네트워크) · `bootm`·`booti`(커널 기동).
  **이 목록이 곧 「이 프롬프트에서 무엇을 할 수 있는가」다.**

## 직접 해보기

⚠ **개발 보드에서만 하십시오.** 플래시 쓰기 명령은 되돌릴 수 없다.

### 1. 프롬프트에 들어가기

시리얼 콘솔을 연결하고 전원을 넣은 뒤 `bootdelay` 안에 아무 키를 누른다.

```
U-Boot 2022.10 (...)
Hit any key to stop autoboot:  1
=>
```

**여기까지 인증이 없다는 것을 확인하십시오.** 대부분의 개발 보드는 그렇다.

### 2. 현재 설정 보기

```
=> printenv
=> printenv bootdelay bootcmd bootargs
=> bdinfo
```

`bootcmd` 가 실제 부팅 절차다. 읽어보면 커널을 어디서 읽어 어디에 올리는지 알 수 있다.

### 3. 플래시 구조 보기

```
=> mtd list
=> sf probe
```

파티션 이름·크기·오프셋이 나온다. 리눅스의 `/proc/mtd` 와 대조해 보면 같은 구조가
양쪽에서 어떻게 보이는지 알 수 있다.

### 4. 자동부팅 중단을 실제로 막아보기 (빌드 설정)

```bash
cd <u-boot 소스>
grep -E "BOOTDELAY|AUTOBOOT" configs/<보드>_defconfig
```

```
CONFIG_AUTOBOOT=y
CONFIG_BOOTDELAY=1
# CONFIG_AUTOBOOT_KEYED is not set     ← 정지 키 시퀀스 없음 = 아무 키로 진입
```

바꿀 때는 손으로 defconfig 를 고치지 말고 도구를 쓴다. 의존성이 딸려 있다.

```bash
make <보드>_defconfig
make menuconfig          # Boot options → Autoboot options
make savedefconfig
cp defconfig configs/<보드>_defconfig
```

## 더 들어가면

- **SPL / TPL** — 1차·2차 로더 분리. 내부 SRAM 크기 제약 때문에 존재한다.
- **FIT 이미지** — 커널·DTB·initramfs 를 하나로 묶고 **서명**할 수 있는 형식.
  검증 부팅의 출발점이다.
- **검증 부팅(Verified Boot)** — 각 단계가 다음 단계의 서명을 확인한다.
  ROM 이 부트로더를, 부트로더가 커널을 확인하는 사슬.
  최상단 키는 칩 내부 OTP 에 넣는데, **그 기록은 되돌릴 수 없다.**
- **A/B 이중화** — 두 벌의 이미지를 두고 실패 시 되돌린다. 플래시 용량이 두 배 필요하다.
- **`fw_setenv`** — 리눅스가 뜬 상태에서 U-Boot 환경변수를 고치는 도구.
  보드에 없으면 콘솔에서만 바꿀 수 있다.

## 흔한 오해

### 「`bootdelay=0` 이면 중단할 수 없다」

아니다. 소스를 보면 중단 확인 함수가 대기 루프에 들어가기 **전에** 이미 입력된 키를
한 번 본다.

```c
/* common/autoboot.c */
static int abortboot(int bootdelay) {
    if (bootdelay >= 0) { ... }        /* 0 도 여기 들어온다 */
}
static int abortboot_single_key(int bootdelay) {
    if (tstc()) { getchar(); abort = 1; }   /* 루프 전에 먼저 확인 */
    while ((bootdelay > 0) && (!abort)) { ... }
}
```

기동 시점에 키를 누르고 있으면 `0` 으로도 프롬프트에 들어간다.
실제로 막는 값은 **`-2`** 다 — 이 값은 중단 확인 절차 자체를 건너뛴다.

```c
if (s && (stored_bootdelay == -2 ||
     (stored_bootdelay != -1 && !abortboot(stored_bootdelay)))) { ... }
```

`-1` 은 반대로 자동부팅을 하지 않고 프롬프트에 머무는 값이다. 혼동하면 안 된다.

### 「컴파일 설정을 고정하면 끝이다」

`bootdelay` 는 세 곳에서 정해지고 **뒤가 앞을 덮는다.**

```
컴파일 기본값  →  저장매체의 환경변수  →  디바이스 트리
```

컴파일 값만 바꿔도 `setenv bootdelay 3; saveenv` 로 되돌아간다.
U-Boot 소스 주석 자체가 이유를 밝힌다 — 디바이스 트리는 서명할 수 있지만
환경변수는 대개 저장매체에서 읽히기 때문이다.
고정이 필요하면 **서명된 디바이스 트리**에 넣는다.

### 「시리얼 콘솔은 리눅스 로그인이니 root 비밀번호로 막힌다」

같은 UART 포트에 **인증 경계가 다른 두 인터페이스**가 있다.

```
부트로더 단계    인증 없음.  아무 키 → 프롬프트 → 플래시·메모리 직접 조작
운영체제 단계    root 비밀번호
```

보안 문서를 쓸 때 이 둘을 하나로 묶으면 사실과 다른 서술이 된다.
