# Linux 개발환경 · 셸

> 보드에는 IDE 가 없다. 셸이 유일한 창구인 경우가 대부분이다.
> 그리고 카메라 펌웨어의 상당 부분이 실제로 셸 스크립트로 되어 있다.

## 왜 필요한가

임베디드 리눅스 기기에 들어가면 쓸 수 있는 것이 제한적이다.
`bash` 도 없고 `busybox ash` 만 있는 경우가 흔하다.
**호스트에서 되던 스크립트가 보드에서 안 되는 이유**가 여기 있다.

그리고 CGI · 초기화 스크립트 · 배포 절차가 전부 셸이다.
셸을 정확히 쓰는 것이 곧 제품 신뢰성이다.

## 최소 이해 수준

- **보드의 셸은 `bash` 가 아니다.** BusyBox 의 `ash` 나 `dash` 인 경우가 많다.
  **`bash` 전용 문법(bashism)이 안 통한다.**

  | bash 전용 | 이식 가능한 대안 |
  |---|---|
  | `[[ ... ]]` | `[ ... ]` |
  | `$(( ))` 안의 `**` | 곱셈으로 풀어 쓴다 |
  | 배열 `arr=(a b)` | 위치 인자나 문자열 분리 |
  | `${var,,}` (소문자) | `tr '[:upper:]' '[:lower:]'` |
  | `echo -e` | `printf` |
  | `source` | `.` (점) |
  | `function f() {}` | `f() {}` |

  **`printf` 를 쓰는 습관이 `echo` 보다 안전하다** — `echo` 의 동작이 셸마다 다르다.
- **항상 따옴표를 쓴다.** 공백이 있는 값에서 단어 분리가 일어난다.
  ```sh
  rm $f          # f="a b" 면 두 파일을 지우려 한다
  rm "$f"        # 올바르다
  ```
- **오류에서 멈추게 한다.**
  ```sh
  set -eu
  # -e 실패하면 멈춘다   -u 정의되지 않은 변수는 오류
  ```
  ⚠ `set -e` 는 파이프의 중간 실패를 잡지 못한다.
  `bash` 라면 `set -o pipefail` 을 더한다.
- **종료 상태가 인터페이스다.** `0` 이 성공이고 나머지가 실패다.
  ```sh
  if cmd; then ... fi          # 종료 상태로 분기
  cmd || { echo "실패"; exit 1; }
  ```
- **원자적 파일 갱신.** 설정 파일을 직접 덮어쓰면 전원이 나갈 때 반쯤 남는다.
  ```sh
  tmp="$f.tmp.$$"
  printf '%s\n' "$content" > "$tmp" && sync && mv "$tmp" "$f"
  ```
  `mv` 는 같은 파일시스템 안에서 원자적이다.
  → [플래시 · 파일시스템](../BSP/플래시와파일시스템.md)
- **잠금으로 중복 실행을 막는다.**
  ```sh
  exec 9>/run/myscript.lock
  flock -n 9 || { echo "이미 실행 중"; exit 1; }
  ```
  **같은 작업이 둘 돌면 데이터가 망가지는 경우가 실제로 있다.**
- **임시 파일을 안전하게.**
  ```sh
  tmp=$(mktemp) || exit 1
  trap 'rm -f "$tmp"' EXIT INT TERM
  ```
  `trap` 을 걸어 두면 중간에 죽어도 정리된다.
- **비밀 값을 명령행에 두지 않는다.** `ps` 로 다 보인다.
  파일이나 표준 입력으로 넘긴다.
  ```sh
  printf '%s' "$pw" | myprog --password-stdin
  ```

## 직접 해보기

### 1. 보드의 환경 확인

들어가서 가장 먼저 할 일이다.

```sh
echo "$0"; ls -l /bin/sh
busybox 2>&1 | head -5
busybox --list | tr '\n' ' '        # 쓸 수 있는 명령 목록
```

**`busybox --list` 에 없는 명령은 없는 것**이다.
`awk` 가 있어도 BusyBox 판은 기능이 줄어 있다.

### 2. bashism 검사

```bash
checkbashisms myscript.sh          # devscripts 패키지
shellcheck myscript.sh
dash -n myscript.sh                # 문법만 검사 (실행하지 않는다)
```

**`shellcheck` 가 가장 유용하다.** 따옴표 누락을 거의 다 잡아 준다.

```bash
shellcheck -s sh myscript.sh       # POSIX sh 로 검사
```

### 3. 따옴표 문제를 직접 보기

```sh
mkdir -p /tmp/t && cd /tmp/t
touch "a b.txt"
for f in *.txt; do echo 지움: $f;  done      # 두 단어로 쪼개진다
for f in *.txt; do echo 지움: "$f"; done      # 올바르다
```

### 4. 원자적 갱신이 되는지 확인

```sh
# 중간 상태가 보이는지 관찰
( for i in $(seq 1 100000); do echo "line $i"; done > /tmp/big.txt ) &
while [ -f /tmp/big.txt ]; do wc -l < /tmp/big.txt; sleep 0.1; done | head -5
```

줄 수가 늘어나는 것이 보인다 — **읽는 쪽이 반쯤 쓰인 파일을 본다.**
`mv` 방식으로 바꾸면 그 중간 상태가 없다.

### 5. 필수 도구 확인 습관

스크립트 앞에 넣어 두면 보드에서 바로 실패 원인이 나온다.

```sh
for c in openssl md5sum flock printf; do
    command -v "$c" >/dev/null || { echo "없음: $c" >&2; exit 1; }
done
```

**`which` 대신 `command -v`** 를 쓴다 — 이식성이 낫다.

### 6. 자주 쓰는 조합

```bash
# 큰 파일 찾기
du -ah / 2>/dev/null | sort -rh | head -20

# 어느 프로세스가 파일을 잡고 있는지
fuser -v /dev/video0 2>&1
lsof /dev/video0 2>/dev/null

# 특정 프로세스의 열린 파일 수 (fd 누수)
ls /proc/$(pgrep -f myapp)/fd | wc -l

# 시간에 따른 변화 관찰
watch -n1 'grep VmRSS /proc/$(pgrep -f myapp)/status'

# 로그를 따라가며 걸러내기
tail -F /var/log/messages | grep --line-buffered -iE 'error|fail'
```

⚠ `grep` 을 파이프에 넣으면 버퍼링 때문에 출력이 늦게 나온다.
`--line-buffered` 나 `stdbuf -o0` 을 쓴다.

### 7. 보드에 접속하는 수단 정리

```sh
# 시리얼 콘솔 (네트워크가 죽어도 된다)
picocom -b 115200 /dev/ttyUSB0

# 네트워크
ssh root@<보드IP>

# 주소를 모를 때 — 보드 쪽에서 확인
ip -4 addr show
```

**시리얼 콘솔이 최후의 수단**이다. 네트워크 설정을 바꾸는 작업 전에는
반드시 콘솔을 확보해 둔다. → [UART · I2C · SPI · GPIO](../BSP/버스.md)

### 8. 파일을 보드로 옮기기

```bash
scp file root@<보드IP>:/tmp/
# scp 가 없으면
base64 file | ssh root@<보드IP> 'base64 -d > /tmp/file'
# 네트워크가 없으면 TFTP 나 USB
```

⚠ 여러 파일을 압축해 풀 때 **먼저 여유 공간을 확인**한다.
부족하면 조용히 잘린다.

```sh
df -h /대상경로
```

## 더 들어가면

- **초기화 시스템.** BusyBox `init` + `/etc/inittab`, 또는 `systemd`.
  임베디드는 전자가 흔하다. 서비스가 죽었을 때 되살리는 설정이 여기 있다.
  ⚠ **감시 스크립트가 되살리는 중에 손으로 또 띄우면 두 개가 된다.**
  중지할 때는 감시를 먼저 끄거나 `flock` 으로 막는다.
- **`trap` 으로 정리하기.** `EXIT` · `INT` · `TERM` 을 잡아 자식 프로세스를
  정리한다. 안 하면 스크립트가 끝났는데 자식이 남아 돈다.
  ```sh
  child_pid=
  cleanup() { [ -n "$child_pid" ] && kill "$child_pid" 2>/dev/null; }
  trap cleanup EXIT INT TERM
  mydaemon & child_pid=$!
  wait "$child_pid"
  ```
- **CGI 작성 시 주의.** 사용자 입력이 그대로 셸에 들어가면 명령 주입이 된다.
  **값을 셸 명령에 끼워 넣지 않는다.**
  ```sh
  eval "grep $q file"       # 절대 금지
  grep -- "$q" file         # 인자로 넘긴다
  ```
  → [인증과 인가](../보안/인증과인가.md)
- **`dotfiles` 와 편집기.** 보드에는 `vi`(BusyBox 판)만 있는 경우가 많다.
  최소한의 `vi` 조작(`i` `Esc` `:wq` `dd` `/검색`)은 알아 둔다.
- **`ssh` 설정.** 반복 접속이 많으면 호스트 별칭과 키를 설정해 둔다.
  ```
  # ~/.ssh/config
  Host cam
      HostName 192.168.0.10
      User root
      StrictHostKeyChecking no      # 개발 보드에만
  ```
- **셸이 적합하지 않은 경계.** 계산이 많거나 구조체를 다루거나
  성능이 필요하면 C 로 옮긴다. **셸은 조립과 기동에 쓴다.**

## 흔한 오해

### 「호스트에서 되면 보드에서도 된다」

셸이 다르고, 명령이 없고, 있어도 옵션이 줄어 있다.
`sed -i` · `grep -P` · `date -d` 가 BusyBox 에서 안 되는 대표적인 예다.
**보드에서 직접 돌려 보기 전에는 확인된 것이 아니다.**

### 「`set -e` 를 넣으면 안전하다」

파이프의 중간 실패, `if` 조건 안의 실패, 함수 안의 일부 실패를 놓친다.
**중요한 명령은 개별적으로 확인**한다.

### 「셸 스크립트는 임시 코드다」

제품 기능이 셸로 되어 있는 경우가 많다 — 초기화 · CGI · 업데이트.
그러면 그것이 제품 코드이고, **같은 수준의 검토가 필요하다.**

### 「`echo` 는 어디서나 같다」

`echo -n` 과 `echo -e` 의 동작이 셸마다 다르다.
`printf` 를 쓰면 예측 가능하다.

### 「파일을 덮어쓰는 것은 한 동작이다」

`>` 는 먼저 파일을 비우고 쓴다. 그 사이에 전원이 나가면 **내용이 사라진다.**
임시 파일 + `mv` 를 쓴다.

### 「명령행 인자는 안 보인다」

`ps aux` 로 전부 보인다. 비밀번호나 키를 인자로 넘기면 **같은 기기의
다른 사용자에게 노출**된다. 표준 입력이나 파일로 넘긴다.
