# PTZ 모터 구동

> Pan(좌우) · Tilt(상하) · Zoom(확대). 카메라를 물리적으로 움직이는 부분.
> 소프트웨어에서 보면 「좌표를 주면 그 위치로 간다」인데, 그 사이에 기계가 있다.

## 왜 필요한가

고정 카메라로 못 덮는 넓은 구역을 한 대로 감시한다.
그리고 사고 대응에서 **원격으로 방향을 돌려 확인**하는 것이 실제 요구다.

제어 명령은 ONVIF 나 자체 API 로 들어오고, 그것을 모터 펄스로 바꾸는 것이
펌웨어의 일이다. → [ONVIF](../네트워크/ONVIF.md)

## 최소 이해 수준

- **스테퍼 모터가 기본이다.** 펄스 하나에 정해진 각도만큼 돈다.
  위치 센서 없이도 **몇 스텝 보냈는지로 위치를 아는** 것이 장점이다.

  | | 스테퍼 | DC 모터 | BLDC / 서보 |
  |---|---|---|---|
  | 위치 제어 | 펄스 수로 (개루프) | 엔코더 필요 | 엔코더 내장 |
  | 정지 유지 | 전류를 흘려 유지 | 유지 못 함 | 유지 |
  | 소음 | 있다 | 적다 | 적다 |
  | 비용 | 낮다 | 낮다 | 높다 |

  감시 카메라는 대부분 스테퍼다. 고급 제품에 BLDC 가 쓰인다.
- **드라이버 IC 가 필요하다.** SoC 의 GPIO 는 모터를 돌릴 전류를 못 낸다.
  `STEP` · `DIR` · `ENABLE` 세 신호를 드라이버에 주는 구조가 흔하다.
  ```
  SoC ── STEP ──→ 드라이버 ──→ 모터 코일
      ── DIR  ──→
      ── EN   ──→
  ```
- **속도 = 펄스 주파수.** 그래서 **정확한 타이밍이 필요**하고,
  일반 유저 공간 코드로 만들면 지터가 생겨 소리와 진동이 난다.
  PWM 하드웨어나 커널 타이머를 쓴다.
- **가감속(ramping)이 필수다.** 정지에서 갑자기 최고 속도로 펄스를 주면
  **모터가 따라오지 못하고 스텝을 잃는다**(탈조). 그러면 위치를 알 수 없게 된다.
  ```
  속도 ▲
      │      ┌────────┐
      │    ╱           ╲
      │  ╱               ╲
      └─────────────────────→ 시간
       가속   정속    감속
  ```
- **마이크로스테핑.** 한 스텝을 전류 비율로 쪼개 부드럽게 움직인다.
  1/8 · 1/16 이 흔하다. 소음과 진동이 크게 줄지만 **유지 토크가 약간 줄고
  같은 각속도에 펄스가 더 많이 필요**하다.
- **원점(홈) 잡기.** 개루프이므로 전원을 켜면 현재 위치를 모른다.
  리밋 스위치나 포토 인터럽터를 만날 때까지 천천히 돌려 기준점을 찾는다.
  **이 과정이 부팅 시간에 포함된다.**
- **기계적 한계.** Pan 은 360° 연속 회전이 가능한 설계도 있고
  한계가 있는 설계도 있다. Tilt 는 대개 제한된다.
  **소프트웨어에서 한계를 넘어 명령하면 기계가 부딪친다.**
- **프리셋과 투어.** 자주 보는 위치를 저장하고, 순서대로 순회한다.
  저장값은 비휘발 영역에 둔다. → [플래시 · 파일시스템](../BSP/플래시와파일시스템.md)
- **줌은 별개다.** 렌즈 안의 모터로 초점거리를 바꾼다(광학 줌).
  줌을 바꾸면 **초점이 어긋나므로 AF 가 따라와야** 한다.
  → [ISP 파이프라인](../영상/ISP.md)

## 직접 해보기

### 1. 제어 인터페이스 확인

리눅스에서 모터를 어떻게 다루는지부터 본다.

```bash
# PWM 이 노출돼 있는지
ls /sys/class/pwm/
cat /sys/class/pwm/pwmchip0/npwm

# GPIO 로 직접 하는 구조인지
gpioinfo | grep -iE 'step|dir|motor|pan|tilt'
```

벤더가 전용 드라이버와 `ioctl` 인터페이스를 주는 경우도 많다.

```bash
ls /dev | grep -iE 'ptz|motor|servo'
```

### 2. PWM 으로 펄스 내보내기

```bash
cd /sys/class/pwm/pwmchip0
echo 0 > export
cd pwm0
echo 1000000 > period        # 1ms = 1kHz
echo 500000  > duty_cycle    # 50%
echo 1 > enable
# 멈추기
echo 0 > enable
```

⚠ **먼저 모터를 떼거나 기계적 한계에서 멀리 둔 상태**에서 시험한다.
한계에 부딪친 채로 계속 펄스를 주면 모터와 기구가 손상된다.

### 3. 스텝당 각도를 실측하기

데이터시트 값과 실제가 다를 수 있다(기어비 때문).

```
① 원점으로 보낸다
② 정해진 펄스 수(예: 1000)를 보낸다
③ 실제 회전 각도를 측정한다 (각도기 · 벽의 표시 이용)
④ 각도 ÷ 펄스 수 = 스텝당 각도
```

**이 값이 좌표 변환의 기준**이 된다. ONVIF 의 정규화 좌표(-1~1)를
펄스 수로 바꿀 때 쓴다.

### 4. 탈조를 재현하고 한계 속도 찾기

```
① 가속 없이 낮은 주파수로 펄스를 준다 → 정상 동작
② 주파수를 단계적으로 올린다
③ 어느 지점에서 「윙」 소리만 나고 움직이지 않는다 → 탈조
④ 그 아래를 최대 속도로 정한다
```

가감속을 넣으면 ③의 지점이 올라간다. **가감속의 효과를
숫자로 확인할 수 있는 시험**이다.

### 5. 위치 누적 오차 재기

```
① 원점을 잡는다
② 좌우로 100회 왕복시킨다
③ 다시 원점 명령을 보내고, 실제로 원점에 오는지 본다
```

어긋나면 탈조가 쌓인 것이다. **주기적으로 원점을 다시 잡는 것**이
실전 대응이다.

### 6. 소비 전류 확인

```
정지 유지    ___ mA   (스테퍼는 멈춰 있어도 전류를 쓴다)
이동 중      ___ mA
가속 순간    ___ mA   ← 최대
```

**가속 순간의 전류가 전원 설계의 기준**이다.
PoE 예산을 넘기면 모터가 움직일 때 보드가 리셋된다.
→ [전원 · 레귤레이터](전원.md)

### 7. ONVIF 로 제어해 보기

```python
from onvif import ONVIFCamera
cam = ONVIFCamera('<주소>', 80, 'user', 'pass')
ptz = cam.create_ptz_service()
prof = cam.create_media_service().GetProfiles()[0]

# 연속 이동 (속도 지정)
ptz.ContinuousMove({'ProfileToken': prof.token,
                    'Velocity': {'PanTilt': {'x': 0.3, 'y': 0.0}}})
import time; time.sleep(1)
ptz.Stop({'ProfileToken': prof.token})

# 절대 위치
ptz.AbsoluteMove({'ProfileToken': prof.token,
                  'Position': {'PanTilt': {'x': 0.5, 'y': -0.2}}})
```

**`ContinuousMove` 는 반드시 `Stop` 이 필요하다.**
클라이언트가 죽으면 카메라가 계속 도는 문제가 생기므로
서버 쪽에 타임아웃을 두어야 한다.

## 더 들어가면

- **S 곡선 가감속.** 직선 가속보다 진동이 적다. 가속도의 변화율까지 제한한다.
  고배율 줌에서 진동이 화면 흔들림으로 바로 보이기 때문에 값이 있다.
- **전류 제어(초핑).** 스테퍼 드라이버가 코일 전류를 일정하게 유지한다.
  전류를 낮추면 발열과 소음이 줄지만 토크가 줄어든다.
  **정지 유지 중에는 전류를 낮추는 것**이 흔한 최적화다.
- **탈조 검출.** 고급 드라이버는 역기전력으로 탈조를 감지해 알려준다.
  이것이 있으면 원점 재탐색을 자동으로 걸 수 있다.
- **자동 추적.** 분석 결과의 객체 좌표를 PTZ 명령으로 바꿔 따라간다.
  **제어 루프의 지연이 전체 지연에 그대로 더해지므로**
  영상 지연이 크면 추적이 진동한다. → [Video Analytics](../관제/VideoAnalytics.md)
- **기구 수명.** 왕복 횟수에 수명이 있다. 투어를 과하게 돌리면
  기어가 마모된다. 사양서의 왕복 횟수를 넘지 않게 운영 설정을 제한한다.
- **온도 영향.** 저온에서 그리스가 굳어 토크가 더 필요하다.
  실외 제품은 **저온 기동 시험**이 따로 있다.

## 흔한 오해

### 「좌표를 주면 그 위치로 간다」

개루프에서는 「그만큼 펄스를 보냈다」일 뿐이다. 탈조가 있으면
실제 위치와 어긋나고, 그 오차는 **누적된다.**
프리셋이 조금씩 틀어지는 문제가 여기서 나온다.

### 「속도를 올리면 더 빨리 도착한다」

탈조가 나면 아예 안 움직인다. 그리고 가감속 없이 속도만 올리면
정지할 때 관성으로 지나친다. **최고 속도보다 가감속 설계가 도착 시간을
더 많이 좌우한다.**

### 「스테퍼는 멈춰 있으면 전력을 안 쓴다」

유지 토크를 내기 위해 전류를 계속 흘린다. 오히려 **정지 상태가
계속 발열하는 상태**다. 유지 전류를 낮추거나, 기구적으로 자립하는
설계라면 전원을 끊는다.

### 「PTZ 제어는 응용 코드에서 GPIO 토글로 하면 된다」

유저 공간 타이머는 정확하지 않다. 스케줄러에 밀리면 펄스 간격이 흔들려
소음과 진동이 생기고 탈조가 난다. **PWM 하드웨어나 커널 쪽**에서 만들어야 한다.
→ [디바이스 드라이버](../BSP/디바이스드라이버.md)

### 「기계적 한계는 하드웨어가 알아서 막는다」

리밋 스위치가 있어도 소프트웨어가 계속 밀면 모터는 계속 밀어 댄다.
**소프트웨어 한계값을 기계 한계보다 안쪽에 두는 것**이 원칙이다.

### 「줌을 바꿔도 PTZ 속도는 같아도 된다」

고배율에서는 같은 각속도가 화면에서 훨씬 빠르게 보인다.
**줌 배율에 비례해 속도를 줄이지 않으면** 조작이 불가능하다.
실제 제품은 이 보정을 넣는다.
