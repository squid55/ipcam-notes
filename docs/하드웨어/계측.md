# 오실로스코프 · 로직 애널라이저

> 전압을 시간축으로 그려 보는 장비. 「신호가 아예 없는가」와
> 「신호는 있는데 상대가 응답하지 않는가」를 가른다.

## 왜 필요한가

소프트웨어 쪽에서 볼 수 있는 것은 「실패했다」까지다.
왜 실패했는지는 선 위의 파형에 있다.

I2C 로 센서가 안 잡힐 때, 회로도와 드라이버를 아무리 봐도 답이 없을 수 있다.
**클럭이 나가고 있는지 한 번 보면** 문제 범위가 절반으로 줄어든다.

## 최소 이해 수준

- **두 장비의 역할이 다르다.**

  | | 오실로스코프 | 로직 애널라이저 |
  |---|---|---|
  | 보는 것 | 전압의 실제 모양 | 0/1 논리값 |
  | 채널 수 | 2~4개 | 8~32개 |
  | 강한 곳 | 신호 품질 · 노이즈 · 전압 레벨 | 프로토콜 해석 · 긴 기록 |
  | 쓰는 때 | 「신호가 이상하다」 | 「데이터가 틀렸다」 |

  **둘 다 필요하고, 시작은 로직 애널라이저가 값싸고 실용적이다.**
- **대역폭이 핵심 사양이다.** 보려는 신호 주파수의 **5배 이상**을 권한다.
  100MHz 오실로스코프로 50MHz SPI 클럭을 보면 모양이 뭉개진다.
- **샘플링 속도와 메모리 깊이.** 샘플링이 빨라도 메모리가 얕으면
  긴 시간을 못 담는다. **부팅 전 구간을 보려면 메모리 깊이**가 중요하다.
- **트리거가 전부다.** 언제 화면을 멈출지 정하는 조건.
  - 에지 트리거 — 상승/하강 순간
  - 펄스 폭 — 너무 짧거나 긴 펄스
  - 시리얼 트리거 — 특정 I2C 주소나 UART 문자
  **「한 번만 일어나는 문제」는 트리거를 잘 걸어야 잡힌다.**
- **프로브를 먼저 보정한다.** 10:1 감쇠 프로브는 보정 커패시터가 있고,
  맞지 않으면 사각파가 기울거나 뾰족해진다.
  **보정하지 않고 측정한 값은 신뢰할 수 없다.**
- **접지 클립을 짧게.** 접지선이 길면 고속 신호에 링잉이 보인다.
  그것은 회로의 문제가 아니라 측정의 문제다.
- **로직 애널라이저의 프로토콜 디코더.** I2C · SPI · UART 를
  자동으로 해석해 바이트로 보여준다. **이것이 실무 가치의 대부분이다.**

## 직접 해보기

### 1. 처음 할 일: 프로브 보정

```
① 프로브를 오실로스코프의 보정 출력(CAL / 1kHz)에 물린다
② 사각파를 띄운다
③ 모서리가 평평해지도록 프로브의 트리머를 돌린다
```

기울어져 있으면 저주파가 왜곡되고, 뾰족하면 고주파가 과장된다.

### 2. I2C 가 살아 있는지 보기

가장 자주 쓰는 측정이다.

```
① SCL 과 SDA 에 프로브 두 개를 물린다
② 트리거: SDA 하강 에지, 홀드오프를 짧게
③ 보드에서 i2cdetect 를 돌린다
```

```bash
i2cdetect -y -r 1
```

무엇이 보이는지로 원인이 갈린다.

| 파형 | 뜻 |
|---|---|
| SCL·SDA 둘 다 움직임 없음 | 컨트롤러가 전송하지 않는다 → 드라이버·디바이스트리 |
| SCL 은 나가고 SDA 는 항상 High | 슬레이브가 응답하지 않는다 → 전원·주소·배선 |
| SDA 가 주소 뒤 9번째 비트에서 Low | **ACK 가 왔다** → 통신 성립. 문제는 위 계층 |
| SDA 가 Low 에 붙어 있다 | 버스가 굳었다 → 복구 절차 필요 |
| 레벨이 3.3V 에 못 미침 | 풀업 저항 문제 |

→ [UART · I2C · SPI · GPIO](../BSP/버스.md)

### 3. UART 보율 알아내기

콘솔에서 글자가 깨질 때 실제 보율을 역산할 수 있다.

```
① TX 선에 프로브를 물린다
② 가장 짧은 펄스의 폭을 측정한다 (커서 기능)
③ 보율 = 1 ÷ 그 폭
```

`8.68μs` → 약 115200. `104μs` → 9600.
**추측해서 바꿔 보는 것보다 빠르다.**

### 4. 전원 강하 잡기

```
① 전원 레일에 프로브 (DC 커플링, 오프셋을 써서 확대)
② 트리거: 하강 에지, 임계값을 정상값의 90%
③ 문제가 나는 동작을 실행한다
```

리셋 신호도 같이 물리면 **강하와 리셋의 순서**를 볼 수 있다 —
강하가 먼저면 전원 문제, 리셋이 먼저면 소프트웨어나 워치독이다.
→ [전원 · 레귤레이터](전원.md)

### 5. 로직 애널라이저로 프로토콜 해석

값싼 USB 로직 애널라이저와 오픈소스 소프트웨어로 충분하다.

```bash
# sigrok
sigrok-cli --scan
sigrok-cli -d fx2lafw --config samplerate=4m \
  --channels D0=SCL,D1=SDA --samples 4M \
  -P i2c:scl=SCL:sda=SDA -A i2c=address-read:address-write:data-read:data-write
```

```bash
# GUI
pulseview
```

**바이트로 해석된 결과가 나오면** 드라이버가 보낸 레지스터 값과
대조할 수 있다. 이것이 센서 초기화 디버깅의 표준 방법이다.

### 6. 한 번만 일어나는 문제 잡기

```
① 단일(Single) 트리거 모드로 둔다
② 트리거 조건을 이상 상태에 맞춘다 (예: 펄스 폭 < 1μs)
③ 걸릴 때까지 기다린다 — 몇 시간이어도 된다
```

**평균 화면으로는 절대 안 보이는 문제**가 이렇게 잡힌다.

### 7. 장비 없이 할 수 있는 것

```bash
# GPIO 를 토글해 소프트웨어 타이밍을 재는 대용
# (핀 하나를 코드 구간 앞뒤에서 토글하고 그 폭을 측정)
```

오실로스코프가 있으면 **코드 구간의 실제 실행 시간**을 μs 단위로 잴 수 있다.
`printf` 로는 알 수 없는 값이다.

## 더 들어가면

- **FFT · 스펙트럼.** 노이즈의 주파수를 보면 출처를 추정할 수 있다.
  스위칭 레귤레이터 주파수와 일치하면 그쪽이다.
- **아이 다이어그램.** 고속 직렬 신호의 품질을 겹쳐 보는 방법.
  MIPI · 이더넷 같은 차동 신호에서 쓴다. 전용 프로브가 필요하다.
- **차동 프로브.** 차동 쌍을 정확히 보려면 두 신호의 차를 재는 프로브가 필요하다.
  단선 프로브 두 개로 뺀 값은 정확하지 않다.
- **전류 프로브.** 전압이 아니라 전류를 본다.
  인러시와 모터 가속 전류를 볼 때 유용하다. → [PTZ 모터](PTZ.md)
- **커서와 자동 측정.** 주파수 · 듀티 · 상승 시간 · 최대/최소를 자동으로 낸다.
  눈으로 읽는 것보다 정확하고 기록하기 쉽다.
- **스크린샷과 데이터 저장.** 측정을 캡처해 문서에 남긴다.
  **증빙이 필요한 제품 개발에서는 이것이 산출물**이 된다.

## 흔한 오해

### 「오실로스코프는 하드웨어 담당자의 장비다」

소프트웨어 쪽에서 「내 코드가 신호를 내보냈는가」를 확인하는 데 가장 확실한 도구다.
드라이버가 `write()` 를 성공으로 돌려줬어도 선에 아무 것도 안 나갈 수 있다.

### 「파형이 깨끗하면 정상이다」

전기적으로 정상이어도 내용이 틀릴 수 있다. **레벨과 타이밍은 오실로스코프,
내용은 로직 애널라이저**로 본다. 두 질문을 섞으면 진단이 헤맨다.

### 「링잉이 보이니 회로가 나쁘다」

접지 클립이 길어서 생긴 측정 오차일 수 있다.
짧은 접지 스프링으로 바꿔 다시 재본 뒤에 판단한다.

### 「대역폭이 높으면 좋다」

필요 이상은 비용이다. I2C(400kHz) · UART(115200) · GPIO 수준이면
**20~100MHz 로 충분하다.** 고속 직렬을 봐야 할 때만 상위 장비가 필요하다.

### 「측정은 문제가 생긴 뒤에 하면 된다」

정상 상태의 파형을 미리 저장해 두면 비교가 가능해진다.
**기준이 없으면 「이게 이상한 건가」를 판단할 수 없다.**
보드를 처음 받았을 때 주요 신호를 한 번 떠 두는 편이 낫다.

### 「전원을 켠 채로 프로브를 옮겨도 된다」

접지 클립을 전원 노드에 잘못 물리면 단락이 된다.
**접지를 먼저 물리고, 신호 프로브를 나중에** 대는 순서를 지킨다.
가능하면 전원을 끄고 옮긴다.
