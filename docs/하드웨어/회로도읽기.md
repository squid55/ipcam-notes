# 회로도 읽기

> 회로를 설계하지 않더라도, 회로도를 읽을 수 있으면
> 「이건 소프트웨어 문제가 아니다」를 몇 시간 안에 판정할 수 있다.

## 왜 필요한가

소프트웨어로 아무리 고쳐도 안 되는 것들이 있다.
**부품이 안 붙어 있으면 기능이 존재하지 않는다.**

평가 보드(EVK)에서 특히 그렇다. 양산 보드와 회로가 다르고,
비용이나 안전 때문에 **일부 회로를 일부러 비워 둔다.**
그 사실을 모르면 데이터시트에 있는 기능을 몇 주 동안 찾게 된다.

## 최소 이해 수준

- **문서가 셋이다.** 회로도(schematic)는 연결 관계, BOM 은 부품 목록,
  조립도(assembly drawing)는 기판 위 위치다. **세 개를 함께 봐야** 판단이 된다.
- **부품 번호 규칙.** `R` 저항 · `C` 커패시터 · `L` 인덕터 · `D` 다이오드 ·
  `Q` 트랜지스터 · `U` IC · `J`/`CN` 커넥터 · `TP` 테스트 포인트 · `SW` 스위치.
- **미실장 표기가 핵심이다.** 회로도에 있지만 기판에는 없는 부품.
  표기가 여러 가지다.

  | 표기 | 뜻 |
  |---|---|
  | `NC` | Not Connected 또는 **No Component** — 문맥을 봐야 한다 |
  | `DNP` | Do Not Populate — 실장하지 않음 |
  | `NP` / `NM` | Not Populated / Not Mounted |
  | `OPT` | Optional — 선택 실장 |
  | BOM 수량 `0` | 실장하지 않음 |

  ⚠ **`NC` 는 두 가지 뜻**이다. 핀 옆의 `NC` 는 「이 핀은 연결하지 않는다」이고,
  부품 옆의 `NC` 는 「이 부품을 붙이지 않는다」다. 헷갈리면 BOM 수량을 본다.
- **점퍼와 옵션 저항.** `0Ω` 저항이나 솔더 점퍼로 **두 경로 중 하나를 선택**한다.
  부팅 모드 · I2C 주소 · 클럭 소스가 이런 식으로 정해지는 경우가 많다.
  회로도에서 `1-2` / `2-3` 표기를 찾는다.
- **풀업·풀다운.** 신호선이 떠 있지 않게 저항으로 기준을 준다.
  **없으면 값이 불안정**하고, 잘못된 쪽으로 있으면 리셋이 계속 걸린다.
- **전원 도메인.** `3V3` · `1V8` · `VDD_CORE` 처럼 전압별로 망이 나뉜다.
  서로 다른 도메인을 직결하면 부품이 죽는다. → [전원 · 레귤레이터](전원.md)
- **네트 이름을 따라가는 것이 읽기의 전부다.** 회로도는 여러 장으로 나뉘어 있고,
  같은 네트 이름이 여러 장에 나타난다. **이름으로 검색**해서 잇는다.
- **핀 이름과 기능 다중화.** 하나의 SoC 핀이 UART·GPIO·SPI 중 하나로 쓰인다.
  회로도의 이름이 그 보드에서 의도한 용도를 알려준다.
  실제 설정은 디바이스트리에 있다. → [디바이스 트리](../BSP/디바이스트리.md)

## 직접 해보기

### 1. 기능이 실제로 붙어 있는지 확인하는 순서

```
① 회로도에서 그 기능의 블록을 찾는다 (네트 이름으로 검색)
② 관련 부품 번호를 적는다 (R__, C__, Q__, U__)
③ BOM 에서 그 번호를 찾아 수량과 부품번호가 있는지 본다
④ 조립도에서 기판 위 위치를 확인한다
⑤ 실물 기판의 그 자리를 눈으로 본다 — 빈 패드인지
```

**⑤까지 가야 확정된다.** 문서와 실물이 다른 경우가 있다.

### 2. 미실장 부품을 한꺼번에 찾기

BOM 이 CSV 라면 바로 걸러진다.

```bash
# 수량이 0 이거나 DNP/NP 표기가 있는 줄
awk -F, 'tolower($0) ~ /dnp|do not populate|not populated/ || $3 == 0' bom.csv
```

PDF 회로도라면 텍스트로 뽑아서 찾는다.

```bash
pdftotext -layout schematic.pdf - | grep -niE 'dnp|not populate|no component|^nc$' | head -40
```

### 3. 네트를 추적하기

```bash
pdftotext -layout schematic.pdf - > /tmp/sch.txt
grep -n 'CAM_RESET' /tmp/sch.txt      # 그 네트가 나오는 모든 장
```

두 곳 이상에서 나오면 그 장들을 이어 읽는다.

### 4. 실물에서 도통 확인

전원을 **끄고** 멀티미터의 도통 모드로 확인한다.

```
① 커넥터 핀 ↔ 칩 핀 사이가 이어져 있는가
② 풀업 저항이 붙어 있는가 (전원과 신호선 사이 저항값)
③ 전원 핀에 전압이 오는가 (전원을 켜고 DC 전압 모드)
```

⚠ **전원을 켠 상태에서 도통 모드를 쓰지 않는다.** 측정값이 무의미하고
장비에 무리가 간다.

### 5. 테스트 포인트를 미리 찾아 두기

`TP` 로 표시된 자리가 측정용이다. 문제가 생긴 뒤에 찾으면 늦다.
**보드를 받았을 때 전원 · 리셋 · UART 의 TP 위치를 표시해 두면**
나중에 크게 아낀다. → [오실로스코프](계측.md)

### 6. 보드 리비전을 기록하기

```bash
# 기판에 인쇄된 리비전을 사진으로 남긴다
# 소프트웨어 쪽 문서에도 적어 둔다
```

리비전이 다르면 회로가 다르다. **「같은 보드인데 동작이 다르다」의
절반이 리비전 차이**다.

## 더 들어가면

- **블록 다이어그램을 먼저 본다.** 회로도 1장이 대개 블록도다.
  전체 구조를 잡고 나서 세부 장으로 내려가는 것이 빠르다.
- **차동 쌍 표기.** `_P` / `_N` 쌍은 반드시 같이 배선된다.
  MIPI · USB · 이더넷이 여기 해당한다. → [MIPI CSI-2](../영상/MIPI-CSI2.md)
- **디커플링 커패시터.** IC 전원 핀마다 붙는 작은 커패시터.
  기능이 아니라 안정성을 위한 것이고, **회로도에서 대부분의 부품이 이것**이다.
  읽을 때 건너뛰어도 된다.
- **레벨 시프터.** 1.8V 와 3.3V 를 잇는 곳에 들어간다.
  없이 직결된 곳이 있으면 설계 문제일 수 있다.
- **ESD 보호와 TVS.** 외부로 나가는 커넥터에 붙는다.
  EVK 에서 생략되는 경우가 있어 정전기에 약하다.
- **KiCad 로 회로도를 열 수 있다.** 소스 파일(`.kicad_sch`)을 받았다면
  네트 검색과 크로스 프로브가 가능해 PDF 보다 훨씬 빠르다.

## 흔한 오해

### 「데이터시트에 있으니 보드에서 쓸 수 있다」

가장 비싼 오해다. SoC 가 지원하는 것과 **그 보드가 지원하는 것**은 다르다.

실측 예 둘.

- 칩의 보안 기능을 켜려면 특정 전압을 인가하는 회로가 필요한데,
  EVK 에는 **그 회로의 부품 다섯 개가 미실장**이었다.
  기능을 쓰려면 기판을 리워크해야 했다. 소프트웨어로는 방법이 없었다.
- 시각이 매일 조금씩 밀리는 문제를 소프트웨어에서 찾고 있었는데,
  원인은 **RTC 백업 배터리가 실장되지 않은 것**이었다.
  전원을 내리면 시계가 유지될 근거가 없었다.

⇒ **「없을 수도 있다」를 의심 목록의 앞쪽에 둔다.**
특히 시각 · 보안 · 전원 관련 기능에서 자주 생긴다.

### 「회로도만 보면 된다」

회로도는 **설계 의도**이고, BOM 과 조립도가 **실제로 붙은 것**을 말한다.
셋이 어긋나는 경우가 실제로 있고, 그때 기준은 실물이다.

### 「EVK 에서 동작하면 양산 보드에서도 동작한다」

반대 방향도 성립하지 않는다. EVK 에만 있는 회로(디버그 UART · JTAG · 점퍼)와
양산에만 있는 회로(보안 퓨징 · 워치독)가 각각 있다.
**두 보드의 차이 목록을 문서로 만들어 두는 것**이 제품 개발의 실무다.

### 「`NC` 핀은 아무것도 연결하면 안 된다」

칩의 `NC` 핀은 보통 그렇지만, 일부 데이터시트는
「NC 핀을 GND 에 연결할 것」을 요구한다. **핀 설명을 읽어야** 한다.

### 「소프트웨어 사람이 회로도를 볼 필요는 없다」

문제의 경계를 정하는 데 필요하다. 「여기까지는 하드웨어 문제」를
짚어 줄 수 있으면 하드웨어 담당자와의 대화가 몇 배 빨라진다.
전부 이해할 필요는 없고, **네트를 따라가고 미실장을 확인할 수 있으면 충분하다.**
